# TASK: OS-01 – GHOSTOS Build Chain Setup

## 1. Ziel des Tasks
Aufsetzen einer reproduzierbaren Build-Umgebung für GHOSTOS BlackRoot,
basierend auf AOSP oder einer gehärteten Variante (z. B. GrapheneOS-Fork),
für mindestens **ein Referenzgerät** (z. B. Pixel 6/7).

Ziel ist:
- funktionierende Build-Chain,
- dokumentierter Setup-Prozess,
- erstes Minimal-Image (Debug/Dev-Status, noch nicht produktiv).

---

## 2. Anforderungen

### 2.1 Basiswahl
- Entscheidung für eine der Basisplattformen:
  - AOSP (Android Open Source Project)  
  - oder gehärtete Basis wie GrapheneOS-Fork
- Entscheidung dokumentieren in:
  - `rom_ghostos/BUILD_NOTES.md`

### 2.2 Zielgeräte (erste Welle)
- mindestens **ein Pixel-Gerät**, empfohlen:
  - Pixel 6 / 6a
  - oder Pixel 7 / 7a
- Geräteliste dokumentieren in:
  - `rom_ghostos/DEVICE_SUPPORT.md`

### 2.3 Build-Umgebung
- Build-Umgebung für Linux (Ubuntu / Debian-basiert) beschreiben:
  - notwendige Pakete
  - benötigter Speicherplatz
  - empfohlene CPU/RAM-Anforderungen
- Keine proprietären Google-Binaries in Git einchecken,
  nur Hinweise, wo diese zu beziehen sind (falls nötig).

---

## 3. Verzeichnisstruktur

Der Ordner `rom_ghostos/` soll mindestens enthalten:

rom_ghostos/
├── BUILD_NOTES.md
├── DEVICE_SUPPORT.md
├── env/
│ ├── env.example.sh
│ └── setup.md
├── scripts/
│ ├── fetch_sources.sh
│ ├── build_rom.sh
│ └── clean_build.sh
└── out/
└── (ignoriert per .gitignore)

yaml
Code kopieren

**scripts/fetch_sources.sh**
- lädt AOSP/GrapheneOS-Quellen (repo sync / git clone)
- legt Quellen außerhalb des Git-Repos ab (z. B. `~/android/ghostos-src`)

**scripts/build_rom.sh**
- startet den Build-Prozess (z. B. `source build/envsetup.sh && lunch ... && m otapackage`)

**scripts/clean_build.sh**
- räumt temporäre Build-Artefakte auf

---

## 4. Dokumentation

### 4.1 BUILD_NOTES.md
Muss enthalten:
- gewählte Basis (AOSP/GrapheneOS)
- Version/Branch (z. B. android-14.0.0_rXX)
- bekannte Limitierungen
- benötigte Vendor-Binaries (nur referenziert, nicht im Repo)

### 4.2 DEVICE_SUPPORT.md
Muss enthalten:
- Liste unterstützter Geräte (Codename + Marketingname)
- Status pro Gerät:
  - BOOTING / PARTIALLY WORKING / BROKEN
- bekannte Issues (z. B. Kamera, Modem, Fingerprint)

### 4.3 env/setup.md
- Anleitung:
  - OS-Voraussetzungen (Ubuntu Version etc.)
  - Installation aller benötigten Pakete
  - Setup des Java/Android-Toolchains
  - Beispiel für `env.example.sh` (PATH, CCACHE, JAVA_HOME, etc.)

---

## 5. Deliverables

- funktionsfähige Skripte:
  - `fetch_sources.sh`
  - `build_rom.sh`
  - `clean_build.sh`
- vollständige Doku:
  - BUILD_NOTES.md
  - DEVICE_SUPPORT.md
  - env/setup.md + env.example.sh
- erster erfolgreicher Testbuild (lokal), dokumentiert in BUILD_NOTES.md:
  - Build-Befehl
  - Dauer
  - Ergebnis (Image-Datei vorhanden)

---

## 6. Tests

### 6.1 Build-Test
- Build einmal vollständig durchlaufen lassen
- Ergebnis: flashbares oder zumindest erzeugtes ROM-Image

### 6.2 Reproduzierbarkeit
- zweiter Build mit gleicher Umgebung:
  - Ergebnis konsistent (Checksum kann abweichen, aber Build darf nicht fehlschlagen)

### 6.3 Cleanup-Test
- `clean_build.sh` ausführen
- erneuter Build muss wieder durchlaufen

## 7. Q&A (FAQ)

**F:** Muss OS-01 bereits GHOSTOS-spezifische Härtungen enthalten?  
**A:** Nein. OS-01 fokussiert sich auf das Reproduzierbare-Build-Fundament. Hardening folgt in OS-02/OS-03.

**F:** Müssen wir Vendor-Blobs ins Git-Repo aufnehmen?  
**A:** Nein, niemals. Nur Referenzen und Download-Hinweise in BUILD_NOTES.md.

**F:** Reicht ein Gerät oder müssen es mehrere sein?  
**A:** Für OS-01 reicht ein Referenzgerät (idealerweise Pixel). Mehr Geräte → Folge-Tasks.
