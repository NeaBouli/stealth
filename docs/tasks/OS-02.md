# TASK: OS-02 – Kernel-Hardening & Ressourcen-Isolation

## 1. Ziel des Tasks
Dieser Task erweitert GHOSTOS BlackRoot um Kernel-Härtung,
Ressourcen-Isolation und exklusive Rechte für SecureCall (System-App).

Ziele:
- Mikrofon & Kamera exklusiv nur für SecureCall-App
- restriktive SELinux-Policies
- Entfernen/Deaktivieren unnötiger Kernel-Komponenten
- blockierte Debug-/Developer-Schnittstellen
- Minimierung der Angriffsfläche auf OS-Level

---

## 2. Anforderungen

### 2.1 Kernel-Hardening
Folgende Hardening-Maßnahmen müssen aktiviert/konfiguriert werden:

- Deaktivierte Debug-Interfaces:
  - /proc/kcore
  - /proc/mem
  - kernel debugfs
  - USB-Debugging (ADB) standardmäßig OFF
- Strengere sysctl-Werte:
  - kernel.kptr_restrict = 2
  - kernel.dmesg_restrict = 1
  - kernel.unprivileged_bpf_disabled = 1
- ASLR und Memory Protections:
  - vollständiges KASLR
  - hardened usercopy
  - read-only memory regions wo möglich

### 2.2 SELinux-Policies
Mehrere SELinux-Regeln anpassen:

- Nur SecureCall-App darf:
  - Kamera öffnen
  - Mikrofon öffnen
  - AudioRecord / AudioTrack Assets nutzen
  - Netzwerkverbindungen initiieren (optional)
- Alle anderen Apps:
  - Netzwerkverbot oder nur eingeschränkt (je nach Variante)
  - kein Zugriff auf Kamera/Mikrofon

Dokumentation in:
- `rom_ghostos/policies/selinux/securecall.te`
- `rom_ghostos/policies/selinux/system_ext.te`

### 2.3 Ressourcen-Isolation
Implementierung:

- cgroups zur Priorisierung von SecureCall
- CPU- und IO-Pinning
- Strikte Limits für Hintergrundprozesse
- Deaktivieren von unnötigen Systemdiensten:
  - NFC
  - Bluetooth
  - Nearby Services
  - WebView
  - unnötige Netzwerk-Handler

### 2.4 Exklusive Rechte für SecureCall-App
SecureCall wird System-App mit:

- priv-app privileges
- restriktiver Signaturprüfung
- Hardwarezugriff exklusiv über HAL-Policies
- Audio-Policy:
  - AudioInput = securecall_only
  - AudioOutput = securecall_preferred

## 6. Q&A (FAQ)

**F:** Können wir das Hardening zuerst optional machen?  
**A:** Nein. OS-Variante muss ab Anfang streng sein. Nur Debug-Builds dürfen ausnahmen enthalten.

**F:** Was ist, wenn Audio komplett blockiert wird?  
**A:** Die Policies müssen sorgfältig abgestimmt werden. SecureCall benötigt definierte HAL-Access-Regeln.

**F:** Müssen Kernel-Patches upstreambar sein?  
**A:** Nein, aber sie müssen stabil und dokumentiert sein.
