**Anomalies:**
- FCM persist EACCES on `/app/data/fcm_tokens.json.tmp` — Volume mounted (150MB, ID `143a832d`), but Dockerfile `USER securecall` (uid 1001) has no write permissions on the volume directory created as root by Railway. In-memory FCM works, only persistence across restarts is missing.
- Root cause: `Dockerfile:21 USER securecall` + Railway volume default permissions = uid mismatch
- Fix proposal: Add `RUN mkdir -p /app/data && chown securecall:securecall /app/data` to Dockerfile before USER switch, OR use an entrypoint wrapper that runs `chown` (requires root init). Alternatively: in server.js, have `writeJsonAtomic()` handle missing write permissions and use fallback path `/tmp/securecall-data/`.
- Severity: YELLOW (no user impact since FCM in-memory is OK, but data is lost on redeploy)
**Action:** Plan Dockerfile fix as v1.0.23 item (no hotfix needed)
